## goal
join remote zigbee networks via the same routers.

## Vision
The connection type STAR. One main router and several slave routers. Main router collects all the data over all joined network. slaves have information about local devices.

## to do obviously

2) add field "Pairing port" (TCP port to listen) and button "save" near the port (default 10241).
3) if router role is Main then add table with paired routers. Table contains "Name" (paired router name), "MAC" (MAC address), IP, Port, onLine (small green or gray circle), devices, In (packets in), out (packets out). bellow the table place button "Pair"
4) if the router role is Repeater then add button "Pair to host" to tab "Interconnection" and Host online status (several green or gray circle)
5) each device record must have router id (may be 4 byte). Each paired router in network must have such ID. If device is on local router then value is 0. this ID is needed to determine which router send packet to

## secure
** use shared-secret AEAD over TCP for exchange between routers


## pairing protocol
1) Repeater -> opens port
2)              connects <- Main
3)              handshake <-Main
4) Repeater ->  handshake
5)              ask MAC and Name <- Main
6) Repeater -> sends it's MAC and name
7)             sends it's name, MAC and port (port to listen. to this port will connect Repeater for exchange)  <- Main
8) Repeater _> ok
9)             Sends Ok<- Main
10)             disconnects <- Main

## system parameters exchange
1) Repeater -> opens port
2)              connects <- Main
3)              handshake <-Main
4) Repeater ->  handshake
5)              variable= value <- Main
6) Repeater _> ok
7)             disconnects <- Main

## data exchange protocol
1) Initiator   -> connects to Remote
2) Initiator  -> sends type (1 byte . Packet, setting, event)
2) Initiator  -> sends packet
3)             ok <- Remote
4) Initiator  -> disconnects

Main router checks MAC address of connecting repeater

on steps 3 and 4 the handshake means some sequence of several bytes to determine that it is the routers. For example "ImHere" and answer "copy"
on step 5 Repeater must save retrieved values
On step 6 Main saves Repeater to its table


## pairing on Repeater router
The router switches to wait for incoming connection. It must open port "Pairing port" and wait incoming connection up to 120 seconds. During process "RED" LED must blinking (2 Hz) on host and be visible model dialog with countdown timer and button "Cancel".
During this process Repeater waits incoming connection and exchange data with Main router. Finish until full protocol done, or "cancel" pressed or countDown timer.  Repeater should show on "Interconnect" Ip, name, MAC and online status of Main router.


## pairing on Main router
By clicking button "Add" under list of paired routers show dialog with IP and port (default 10241)  of pairing router, buttons "Start" and "Cancel""". User must fill at least port and optionally IP address.
By "Start" there are two ways: first (1) if IP filled by user and second (2) in another way.

2) If IP address is empty then Main router starts scan all IP addresses in subnet except already paired routers IP and trying to handshake if connection established (pairing protocol exclude points 7-9). If handshake ok then Main show to user found router and ask him is this the router he looked for. If user asked no then Main continued find next. If User answered YES then the Main router starts pairing protocol fully.
1) Start pairing process.

After pairing process succeed Main router adds new router to the table.

## Online checking and status
Main router sends to Repeaters checkAlive with given interval (a new setting "checkAlive Repeaters interval" add to "Interconnect" tab. Min 5 sec, max 600 sec , default 60 sec. If user updates this value then this value must be sent to all Repeaters . See system parameters exchange
Repeater knowing this interval can understand is Main alive or not.


## important
"network role" defines the role of router within a network. "Main" - it is like a router works now.
"Repeater" - means that router works as slave router and intended for transmission commands and data to and from zigbee or local mqtt devices. Such router may have settings like automations, consoles, history storing and so on but these functions will not work.

## How Repeater works
Repeater send ALL zigBee packets it received except duplicate to Main router (data exchange protocol)

## receiving packets from repeater on MAIN router
main router all received packets sends to internal API like it received from zigbee. This gives us more simple logic

## pairing remote zigbee devices
When pairing Main router sends to all remote router command to search devices and itself start this operation too. Remote routers sends it answers from remote zigBee devices if any to main and Main accumulates them in single table like now. Small difference is than if device found on repeater then Main must show this in table and save this to device settings. Then algorithm is like now

## sending to remote zigBee from Main
Main knows where to send packet (local or repeater) because each zigbee device has repeater_Id attribute. Main uses    data exchange protocol to send packets

## parameters controlled only by Main and shared between routers in network.
"Check alive interval", "zigbee search interval". If user change these parameters on main they must be sent to all the network. Wen wain reboots it must share these settings again.

## Blocked functions.
On repeaters tabs "Place", "Devices", "Automation", "Cameras", "Scenes", "Consoles", "Security",  "System"/"Maintenance" (except REBOOT), "System"/"Hardware" (except SPI SPEED, RF update SPI speed, BLUE LED brightness, GREEN LED brightness, use queue for base device commands, Low memory threshold) must be hidden
